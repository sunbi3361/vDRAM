# SAMPLES KNOWLEDGE BASE
# scope: mgpusim/amd/samples | branch: main

## OVERVIEW

This directory contains runnable benchmark entry points and the shared runner that wires benchmarks to either the functional emulator or the timing simulator. Most samples are small `main` packages that parse flags, initialize the runner, construct a benchmark, and start simulation.

## STRUCTURE

- `runner/`: shared driver code used by every sample.
  - `runner.go`: `Runner.Init`, `AddBenchmark`, and `Run`.
  - `flag.go`: all global flags (`-timing`, `-parallel`, `-gpu`, `-arch`, `-report-all`, etc.).
  - `emusystem/`: functional platform builder for emulation mode.
  - `timingconfig/`: timing platform builder; selects GPU configuration, including `virtual-caching`. <!-- sbin_codex -->
- `*/*.go`: sample entry points (for example, `fir/fir.go` and `memcopy/main.go`).
- Repository-root `scripts/benchmarks/samples/`: generated copy area produced by the experiment pipeline. Do not edit.

## WHERE TO LOOK

- Entry pattern: `flag.Parse` → `new(runner.Runner).Init()` → construct benchmark → `runner.AddBenchmark(b)` → `runner.Run()`.
- `runner.Runner`: switches between emulation and timing, applies `-verify` / `-use-unified-memory`, and drives the GPU driver.
- `runner/timingconfig.Builder`: builds PCIe, MMU, driver, and GPU domains; selects `virtual-caching` as a virtual-address L1V/L1S/L2 model. <!-- sbin_codex -->
- `runner/emusystem.Builder`: builds the fast functional platform used when timing mode is disabled.
- `driver.Driver`: host command submission, memory allocation, and kernel launch.

## CONVENTIONS

- Samples must not define their own `-timing`, `-parallel`, `-gpu`, `-arch`, or `-report-all` flags; they come from `runner/flag.go`.
- Mandatory timing flags: `-timing -parallel -gpu=virtual-caching -arch=gcn3 -report-all`. <!-- sbin_codex -->
- Sample-specific flags are registered with `flag` in the sample `main` before `flag.Parse`.
- Pass `runner.Driver()` into the benchmark constructor, then configure benchmark-specific parameters.
- Set `benchmark.Arch = runner.ArchType` when the benchmark needs architecture-specific behavior.
- Use `Runner.AddBenchmarkWithoutSettingGPUsToUse` only when the benchmark itself manages GPU selection.

## ANTI-PATTERNS

- Virtual-caching uses a simplified virtual-address model for L1V, L1S, and L2 data caches; L2D misses/refills and dirty writebacks translate through the per-slice L2 address translator, shared L2TLB, and GMMU at the DRAM boundary. <!-- sbin_codex -->
- Do not rely on `-gpu=mi300a` or other unhandled selectors selecting distinct hardware; they may fall through to `r9nano` defaults. <!-- sbin_codex -->
- Do not edit `scripts/benchmarks/samples/` or any path under `scripts/benchmarks/` as source. It is a disposable copy generated by the experiment pipeline.
- Do not assume `-report-all` output is a CSV in the working directory; metrics are written through the Akita reporter, using `-metric-file-name` when provided.
- Do not add runner-level flags inside individual samples.

## TESTING

- Build a sample with `go build` in its directory.
- Use the root guide's canonical sample command; reduce only the benchmark-specific problem size for a smoke test.
- Check that the simulation completes and metrics are recorded; with `-verify`, the benchmark should print its verification result.
